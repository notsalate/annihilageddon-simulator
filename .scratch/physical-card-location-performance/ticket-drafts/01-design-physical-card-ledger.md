# 01 — Зафиксировать архитектуру PhysicalCardLedger и выбрать ID-resolver

**Что сделать:** принять сохранение уже известной branch-local ссылки как доказанный обязательный контракт `PhysicalCardLedger`, составить исчерпывающий реестр production-путей работы с физическими картами и проверить, существуют ли после их миграции настоящие внешние ID-границы, которым вообще нужен resolver. Измеренные удаления по ID не считаются такой границей: их вызывающий код уже имеет объект карты.

**Блокируется:** ничем — можно начинать сразу.

**Статус:** черновик — ожидает утверждения перед публикацией в GitHub.

## Критерии приёмки

- [ ] Зафиксирован доказанный инвариант: если runtime уже знает карту, он сохраняет и передаёт объект текущей ветки, а не заменяет его ID с последующим обратным поиском.
- [ ] Причинная цепочка и тяжёлый прогон подтверждают основание решения: `TemporaryCardControl` создаёт `1 202 923` поиска, физический `EffectSourceContext` — `2 223`, а удаления по ID при уже известной карте — `8 899`; прямые ссылки покрывают все `1 214 045` измеренных поисков.
- [ ] В реестре перечислены все пути `ID→card`, `card→zone`, полного перечисления и прямых изменений зон, включая категории с нулём в исходном тяжёлом прогоне; для каждого указан целевой API Ledger и тикет миграции.
- [ ] Зафиксирована исходная база: `1 214 045` точечных поисков, `272 352 102` просмотренные карты, `253 747 465` временных записей расположения и исходный result fingerprint.
- [ ] Все сравниваемые варианты одинаково сохраняют известные runtime-ссылки; различается только реализация разрешения ID на зарегистрированных внешних границах.
- [ ] После составления реестра отдельно выделены только настоящие внешние ID-границы, где объект карты невозможно сохранить раньше; измеренные `removeById` к ним не относятся.
- [ ] Безаллокаторный locator измеряется только для найденных настоящих ID-границ; постоянный resolver запускается лишь если их остаточная стоимость становится end-to-end bottleneck выше шума benchmark.
- [ ] Если настоящих ID-границ нет либо gate не открыт, production Ledger не получает постоянную таблицу ID→card; вывод подтверждается измерением.
- [ ] Если gate открыт, общий каталог ID→slot, плотные слоты, `Map`, COW/overlay, object metadata и `WeakMap` проходят одинаковый короткий engine-shaped отбор по чтению ID, мутациям, fork и памяти; только победитель допускается до полного чистого Analyzer AB/BA-сравнения.
- [ ] Точная позиция сравнивается с хранением только зоны; отдельно измеряются чтение, мутации, shuffle, reorder, fork, rollback, allocations, retained memory, sampled GC и полное время.
- [ ] Каждый следующий уровень оптимизации запускается только после измерения предыдущего; пропущенный уровень Performance Mantras отклоняется конкретным инвариантом или end-to-end измерением.
- [ ] Выбранный ID-resolver сохраняет правила, RNG, fingerprints, дерево и изоляцию веток и имеет лучшее полное время без подтверждённой регрессии Simulation.

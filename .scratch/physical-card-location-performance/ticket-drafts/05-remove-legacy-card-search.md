# 05 — Удалить старый поиск и прямые изменения зон

**Что сделать:** завершить contract-фазу: production-код получает карту и её членство только через `PhysicalCardLedger`, а физические зоны меняет только операциями модуля. Полное перечисление остаётся отдельным каноническим API для доказанных потребителей полного снимка.

**Блокируется:** 03 — «Перевести внутренние контексты на живые ссылки карт»; 04 — «Перевести ID-границы и операции карт на PhysicalCardLedger».

**Статус:** черновик — ожидает утверждения перед публикацией в GitHub.

## Критерии приёмки

- [ ] В реестре нет незакрытых legacy-путей `ID→card`, `card→zone` или прямых изменений зон; исключения разрешены только для явно обоснованного полного перечисления.
- [ ] Старый глобальный точечный API удалён или недоступен production-коду; потребители не знают внутренний layout Ledger.
- [ ] Репозиторная проверка блокирует новые обходные вызовы и прямые мутации физических зон.
- [ ] Диагностика показывает ноль вызовов legacy point-lookup API и ноль временных location-records для point-read path.
- [ ] Если по результатам №1 выбран reference-first layout, разрешены только зарегистрированные module-owned boundary scans: они имеют отдельные счётчики, не доступны потребителям и подтверждены как более дешёвые по полному времени, чем постоянный resolver.
- [ ] Полное перечисление сохраняет канонический порядок для invariants и зарегистрированных полных потребителей.
- [ ] Публичные snapshots, события, fingerprints и recurrence keys сохраняют прежнюю форму и значения; полный набор тестов проходит без изменения правил и дерева Analyzer.

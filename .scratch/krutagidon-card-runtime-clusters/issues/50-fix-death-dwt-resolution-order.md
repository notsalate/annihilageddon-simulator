# Исправить порядок смерти, воскрешения и эффектов ЖДК

## Parent

- `.scratch/krutagidon-card-runtime-clusters/cross-source-mechanic-matrix.md`

## What to build

Зафиксировать в движке и документации единый порядок разрешения смерти внутри атаки или другого эффекта:

1. игрок умирает;
2. немедленно восстанавливает жизни;
3. немедленно получает и раскрывает ЖДК;
4. полностью завершается именно атака или эффект, вызвавший смерть;
5. выполняется лицо полученного ЖДК;
6. только затем продолжается внешняя карта, включая следующую отдельную атаку.

## Acceptance criteria

- [ ] `resolvePlayerDeath` наблюдаемо выдаёт события `playerDied → playerResurrected → deadWizardTokenGained`.
- [ ] Один общий resolution boundary ставит лицо полученного ЖДК в FIFO-очередь и выпускает очередь после полного завершения вызвавшей смерть атаки/эффекта, а не всей карты.
- [ ] Все оставшиеся последствия той же смертельной атаки/эффекта завершаются до лица ЖДК; воскрешение и сам жетон уже видны этим последствиям.
- [ ] Fixture с последовательностью `смертельный урон → оставшийся возврат карт` закрепляет порядок: урон и смерть → воскрешение → получение ЖДК → возврат карт → лицо ЖДК.
- [ ] Если одна карта создаёт несколько последовательных атак, лицо ЖДК предыдущей жертвы полностью выполняется до начала следующей атаки.
- [ ] Если один неделимый эффект одновременно создаёт несколько ЖДК, их лица выполняются после этого эффекта в порядке получения.
- [ ] Если лицо ЖДК вызывает новую смерть, новое воскрешение и получение происходят сразу, а новое лицо ждёт завершения текущего лица.
- [ ] Прямая выдача ЖДК без смерти не воскрешает игрока и не наследует прежний death/kill context, но её лицо ждёт завершения непосредственно выдавшего жетон эффекта.
- [ ] Все пути смерти, включая damage, установку жизней и Mayhem, используют один контракт.
- [ ] `docs/rules-canon.md`, `docs/rules-glossary.md`, `docs/mechanics-coverage.md`, cross-source matrix и trace/test fixtures описывают один и тот же порядок.
- [ ] Отдельный регрессионный тест сначала падает на текущем порядке `playerDied → deadWizardTokenGained → playerResurrected` и проходит после исправления.

## Evidence

Текущий движок воспроизводимо выдаёт `playerDied → deadWizardTokenGained → playerResurrected`. Лицевые эффекты ЖДК пока не имеют общей отложенной границы.

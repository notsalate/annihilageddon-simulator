# Exact search-space reduction for Best-Move Analyzer

Дата проверки: 2026-08-28.

## Вывод

Для Analyzer не требуется изобретать новые алгоритмы сокращения пространства состояний. Подходящие теоретические семейства уже существуют:

- `partial-order reduction` для исключения перестановок независимых действий;
- `sleep sets` для отсечения уже представленной перестановки до её выполнения;
- таблица транспозиций для повторного использования уже достигнутого состояния;
- канонизация симметрий для взаимозаменяемых экземпляров карт и игроков, когда такая взаимозаменяемость доказана;
- `branch-and-bound` для точного отсечения ветви, если доказанная верхняя граница не превосходит уже найденного результата.

Однако готовой поддерживаемой TypeScript-библиотеки, которую можно подключить к текущему игровому состоянию и получить эти сокращения без предметной интеграции, при поиске не найдено. Существуют готовые model checker-системы, но они требуют представить игру через их собственную модель переходов.

## Что можно переиспользовать

### Partial-order reduction и sleep sets

Две последовательности представляют один порядок событий, если соседние независимые действия можно переставить без изменения наблюдаемого результата. `Sleep set` переносит по DFS сведения о переходах, которые уже были представлены эквивалентным порядком, и не запускает их повторно.

Это непосредственно соответствует случаю:

```text
S -> K  оставить
K -> S  пропустить, если независимость доказана в исходном состоянии
```

Метод не является игровой эвристикой: он появился для борьбы со взрывом числа перестановок при полном исследовании состояний. Основные источники:

- Patrice Godefroid, [Partial-Order Methods for the Verification of Concurrent Systems](https://patricegodefroid.github.io/public_psfiles/thesis.pdf), 1996.
- Cormac Flanagan, Patrice Godefroid, [Dynamic Partial-Order Reduction for Model Checking Software](https://escholarship.org/content/qt47c9f29c/qt47c9f29c_noSplash_80358420125f3e8fde2042820c861864.pdf), POPL 2005.
- Antti Valmari, [A Stubborn Attack on State Explosion](https://doi.org/10.1007/BF00709154), 1992.
- Официальное краткое описание [partial-order reduction в SPIN](https://web.mit.edu/spin_v6.4.7/Doc/Quick.html).

### Таблица транспозиций

Если разные истории приводят к одному полному состоянию, продолжение из него нужно вычислить один раз. Это покрывает больше случаев, чем только соседние коммутирующие действия.

Для точности ключ должен учитывать всё, что способно изменить будущие переходы и оценку: зоны карт и их порядок, владельцев и контроллеров, рынки и стопки, ЖДК, статусы, текущий ход, незавершённые очереди эффектов, доступные действия и состояние RNG. Один короткий хеш без проверки равенства создаёт риск коллизии; для точного Analyzer хеш должен лишь находить кандидата, а каноническое состояние — подтверждать равенство.

Источник: Albert Zobrist, [A New Hashing Method with Application for Game Playing](https://research.cs.wisc.edu/techreports/1970/TR88.pdf), 1970.

### Symmetry reduction

Состояния можно привести к одному каноническому представлению, если различие состоит только в переименовании действительно взаимозаменяемых объектов. Для Analyzer первым безопасным случаем являются одинаковые экземпляры одной карты в одной зоне, когда их instance ID не наблюдаемы будущими эффектами. Симметрия игроков значительно опаснее: место за столом, свойства, фамильяры и направленные эффекты обычно делают игроков несимметричными.

Источник: E. Clarke, E. Emerson, S. Jha, A. Sistla, [Symmetry Reductions in Model Checking](https://www.cs.cmu.edu/~emc/papers/Conference%20Papers/Symmetry%20Reductions%20in%20Model%20Checking.pdf), 1996.

### Branch-and-bound

После появления `best-only` ветвь можно отбросить, если существует доказанная верхняя граница её лучшего возможного терминального результата и она не лучше уже найденной линии. Это точный метод только при доказанной границе. Оценка «скорее всего уже хуже» превращает его в эвристику.

Для текущего критерия простые границы возможны лишь в ограниченных случаях: например, недостижимость победы при отсутствии доступных эффектов, способных её создать, или максимум дополнительных ПО из оставшихся разрешённых действий. Общая граница для всех карточных эффектов потребует предметной модели.

## Что готовые системы дают и почему их не стоит подключать напрямую сейчас

[LTSmin](https://ltsmin.utwente.nl/) — готовый язык-независимый набор model checking-инструментов с кешированием переходов, partial-order reduction, символьным поиском и многопоточностью. Но новый движок подключается через `PINS`: состояние кодируется целочисленным вектором, а для хорошего сокращения требуется предоставить матрицы зависимостей и сведения о guards. Официальное описание оценивает новый language module примерно в 200–600 строк C glue-кода — без учёта преобразования сложного TypeScript-состояния игры.

SPIN также предоставляет проверенную реализацию partial-order reduction, но ожидает модель на Promela и решает задачу model checking, а не напрямую вызывает существующие `applyAction`, политики выбора и оценку линии.

Следовательно, перенос игры в LTSmin/SPIN возможен, но создаст вторую модель правил. Для Analyzer это повышает риск расхождения с основным движком и, вероятно, будет дороже небольшой собственной реализации поискового слоя.

## Рекомендуемая архитектура

Предметная часть должна остаться в движке:

```typescript
interface AnalyzerTransitionModel {
  listActions(state: GameState): readonly LegalAction[];
  applyAction(state: GameState, action: LegalAction): readonly Successor[];
  stateKey(state: GameState): StateKey;
  statesEqual(left: GameState, right: GameState): boolean;
  areIndependent(
    state: GameState,
    left: LegalAction,
    right: LegalAction
  ): boolean;
}
```

Общий поисковый модуль реализует известные алгоритмы:

1. DFS и `best-only`.
2. Таблицу транспозиций по полному будущезначимому состоянию.
3. Схлопывание одинаковых доступных действий.
4. `Sleep sets` только для доказанно независимых действий.
5. Позже — точные верхние границы и `branch-and-bound`.

Ключевая сложность находится не в самом DFS или `sleep set`, а в корректных предметных функциях `stateKey` и `areIndependent`. Их не может предоставить универсальная библиотека, потому что только движок знает, наблюдаемы ли порядок карт, RNG, instance ID, очередь ЖДК и внешние триггеры.

## Практические правила точности

1. Не считать действия независимыми только по тексту или основному числовому эффекту карты.
2. Требовать одновременно: оба порядка допустимы; оба приводят к равным будущезначимым состояниям; оба одинаково продвигают RNG; ни один порядок не скрывает терминальный исход или выбор.
3. При сомнении оставлять обе ветви.
4. Проверять каждую оптимизацию дифференциально: полный поиск на малых состояниях и сокращённый поиск обязаны выбирать тот же лучший ход.
5. Отдельно измерять число исполненных действий, уникальных состояний, попаданий в таблицу транспозиций и отсечений каждого вида.
6. Эвристики вроде `beam search`, MCTS, случайной выборки и отсечения «слабых» ходов не смешивать с точным режимом: они могут пропустить лучший ход.

## Порядок внедрения

1. Перейти с хранения всех терминальных линий на `best-only` для массовых прогонов.
2. Ввести канонический сериализатор полного будущезначимого состояния и точную проверку равенства.
3. Добавить таблицу транспозиций и измерить долю повторных состояний.
4. Схлопнуть одинаковые экземпляры действий в одном состоянии.
5. Добавить узкий белый список доказанно независимых действий и `sleep sets`.
6. Расширять независимость только через тесты-коммутаторы для каждой поддержанной категории.
7. После профилирования рассматривать `branch-and-bound`, инкрементальный хеш и более дешёвое клонирование состояния.

Alpha-beta здесь пока не является прямой заменой: классический алгоритм предназначен для чередующихся уровней `max`/`min` в состязательном дереве. Текущий поиск одного хода — последовательность решений одного контроллера с вариантами эффектов. Источник: Donald Knuth, Ronald Moore, [An Analysis of Alpha-Beta Pruning](<https://doi.org/10.1016/0004-3702(75)90019-3>), 1975.

# Сводка механик

Этот документ нужен для быстрых решений: что уже можно считать работающим в симуляторе, что работает только частично, а что еще надо сделать перед полным импортом карт.

Это не канон правил. Канон правил лежит в `docs/rules-canon.md`.

Статусы в этом документе относятся к возможностям движка и текущего runtime workflow, а не к полной готовности всех реальных карт с такой механикой.

- Прогресс по конкретным runtime-картам смотреть в generated matrix `.scratch/krutagidon-card-runtime-clusters/card-runtime-cluster-matrix.md`.
- Актуальные guardrails и workflow по runtime-картам проверяются через `npm run report:card-runtime-clusters`.
- `частично` для механики не означает, что все карты с этой механикой уже доведены до `fullRuntime`.
- Ограничения `baselineBot` описывают слабую стратегию выбора, а не автоматически дефект самой engine-механики.

## Как читать статусы

| Статус        | Простыми словами                                                                  |
| ------------- | --------------------------------------------------------------------------------- |
| `готово`      | Для текущего объема симулятора работает и проверено тестами.                      |
| `частично`    | Что-то уже работает, но есть важные пропуски.                                     |
| `минимально`  | Есть только узкое поведение, достаточное для первых тестов или одной карты.       |
| `нет`         | Механики пока нет.                                                                |
| `ждет данные` | Движок в целом готов, но нет нормальных runtime JSON для конкретных карт/жетонов. |

## Чем подтверждено для `готово`

| Механика            | Проверка                                                                                                                                                                |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Мощь                | `tests/action-loop.test.ts`: `playing an add-power card records an immediate effect consequence`                                                                        |
| Лошара              | `tests/action-loop.test.ts`: `gain_status can make the active player Dingler and clamps life to 15`, `active Dingler status gives a 5 VP scoring penalty until removed` |
| Детерминированность | `tests/rng.test.ts`: `seeded RNG produces repeatable sequences`                                                                                                         |

Если у механики позже снова появится статус `готово`, рядом должен быть хотя бы один короткий указатель на тестовый файл или команду, которая это подтверждает.

## Текущие guardrails для неполного покрытия

- Неподдержанные эффекты ЖДК не должны молча становиться silent no-op: runtime уже имеет lifecycle смерти, reset, очередь лиц, базовый штраф и tie-break, но текущую очередь ещё нужно привести к source-sensitive правилам `AttackInstance`/depth-first из канона; реальные лица добавляются только явным mapping.
- Неподдержанные беспределы и мегабеспределы не должны тихо проскакивать через симуляцию: либо их нет в runnable current pack, либо validation/report guardrails не пропускают такой pack, либо runtime падает явной ошибкой при попытке выполнить неподдержанный effect.
- Для pack-level readiness важно различать поддержку механики движком и готовность конкретной runtime-карты. Карта может оставаться `missingRuntime` backlog, даже если базовая механика уже есть в engine.

## Базовые правила партии

| Механика           | Статус     | Что уже работает                                                                                                                          | Чего не хватает                                                                                                                                                                                                                                     |
| ------------------ | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ход игрока         | `частично` | Можно играть карты, покупать карты, активировать постоянки/свойства и завершать ход.                                                      | Правила хода есть, но стратегия пока примитивная: бот обычно играет первую легальную карту, покупает самое дорогое и не умеет хорошо выбирать порядок действий.                                                                                     |
| Завершение хода    | `частично` | Рука сбрасывается, сыгранные непостоянки уходят в сброс, постоянки остаются, мощь обнуляется, рука добирается.                            | Не все будущие “в конце хода” эффекты представлены как отдельные понятные механики.                                                                                                                                                                 |
| Рынок              | `частично` | Основной рынок и рынок легенд пополняются. Если попалась карта события, она разыгрывается и заменяется.                                   | Сложные случаи зависят от полного набора беспределов/мегабеспределов.                                                                                                                                                                               |
| Конец игры         | `частично` | Пустая стопка ЖДК проверяется после `endTurn`; исчерпание основной колоды или колоды легенд обнаруживается фактическим пополнением рынка. | При неудачном Market Flow текущий код завершает игру прямо во время перехода и не даёт ход игроку, на чьём старте refill не удался. По канону нужен pending end condition до конца именно этого хода; его нельзя прогнозировать на предыдущем ходу. |
| Подсчет победителя | `частично` | Считаются ПО карт, ПО ЖДК, штраф лошары, количество легенд и количество ЖДК для тайбрейка.                                                | Будущие scoring-модификаторы карт и жетонов надо добавлять отдельно.                                                                                                                                                                                |

## Карты и ресурсы

| Механика                         | Статус     | Что уже работает                                                                                                                                                   | Чего не хватает                                                                                                                                                       |
| -------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Мощь                             | `готово`   | Карты могут давать мощь. Мощь тратится на покупку и пропадает в конце хода.                                                                                        | Для новых условных эффектов могут понадобиться новые обработчики.                                                                                                     |
| Покупка карт                     | `частично` | Можно покупать из основного рынка, рынка легенд, стопки шальной магии и слота фамильяра.                                                                           | Не все скидки, ограничения и особые покупки будущих карт покрыты.                                                                                                     |
| Чипсины                          | `частично` | Чипсины можно получать, тратить на легенды и на некоторые защиты. Маркер чипсины на рынке частично работает.                                                       | Нужна проверка всех реальных карт, которые работают с чипсинами.                                                                                                      |
| Получить карту                   | `частично` | Карта может быть получена без покупки и попасть в сброс или на верх колоды, если это меняет свойство.                                                              | Engine-механика получения уже есть; ограничение сейчас в том, что `baselineBot` часто использует временную заглушку “первый подходящий”, а не умную стратегию выбора. |
| Сбросить карту                   | `частично` | Можно сбрасывать карты из поддержанных зон.                                                                                                                        | Не все источники и варианты выбора покрыты.                                                                                                                           |
| Уничтожить карту                 | `частично` | Обычные карты уходят в уничтоженные. Шальная магия и вялая палочка возвращаются в свои стопки.                                                                     | Нужны все особые случаи уничтожения из полного набора карт.                                                                                                           |
| Раскрыть / сыграть верхнюю карту | `частично` | Можно раскрывать и играть верхнюю карту своей колоды; если колода пуста, сброс перемешивается.                                                                     | Поддержаны не все источники и назначения.                                                                                                                             |
| Шальная магия                    | `частично` | Покупается за 3. Базовая engine-механика выбора и розыгрыша верхней карты колоды врага уже есть; текущий `baselineBot` при выборе варианта берет первый легальный. | Нужен отдельный умный выбор для ботов и проверка всех краев владения/контроля.                                                                                        |
| Вялая палочка                    | `частично` | Есть как отдельный тип карты, дает -1 ПО, возвращается в стопку при уничтожении.                                                                                   | Нужны все эффекты карт, которые с ней взаимодействуют.                                                                                                                |

## Бой, жизни, смерть

| Механика              | Статус     | Что уже работает                                                                                                                                                                                                                                                                                  | Чего не хватает                                                                                                                                                                                                                                                             |
| --------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Лечение               | `частично` | Лечение не поднимает жизнь выше текущего максимума. Для лошары максимум становится 15.                                                                                                                                                                                                            | Не все цели лечения поддержаны.                                                                                                                                                                                                                                             |
| Установить жизнь      | `частично` | Некоторые эффекты могут поставить жизнь в конкретное значение, например мегабеспредел.                                                                                                                                                                                                            | Нужны все варианты целей и проверки смерти для будущих карт.                                                                                                                                                                                                                |
| Урон без атаки        | `частично` | Урон может убить игрока и запустить смерть/ЖДК/воскрешение.                                                                                                                                                                                                                                       | Поддержаны не все цели. Для главного приза важен не тип урона, а источник: если урон причинил игрок и от этого умер враг, приз должен перейти этому игроку; если смерть от ЖДК, беспредела без владельца или другого не-игрокового источника, приз не меняется.             |
| Атака                 | `частично` | Обычная player-controlled многоцелевая атака сейчас идёт `Defense A → effect A → Defense B → effect B`; Mayhem отдельно собирает все Defense до своего resolution. Поддерживаются target-local branches и атрибуция.                                                                              | Нет явного `DefenseWindowMode` и обычного `COLLECT_ALL_FIRST` для интерактивных атак. Не доказано, что одна `AttackInstance` удерживает все attack-bound consequences и deferred DWT до правильной границы; нет подтверждённого typed outcome для бесконечной attack-chain. |
| Защита                | `частично` | Можно избежать атаки, оплатить несколько видов цены и полностью выполнить ordinary non-ATTACK Defense effects; отдельный защитный урон может дать Trophy.                                                                                                                                         | Порядок окон пока задаётся видом обработчика, а не семантикой каждой ATTACK. Нужны режимы `PER_TARGET`/`COLLECT_ALL_FIRST` и их сочетание с redirect, direct DWT gain и вложенной смертью.                                                                                  |
| Перенаправление атаки | `частично` | В текущем Attack Resolution есть рекурсивная redirect-цепочка, target-local current attacker и общий набор использованных Defense внутри одного разрешения атаки.                                                                                                                                 | Требуется сверка со стабильным `AttackId`, control epochs, переносом полного ATTACK-текста, интерактивным `COLLECT_ALL_FIRST`, card-specific damage source и всеми квотами Defense.                                                                                         |
| Смерть и воскрешение  | `частично` | Движок фиксирует смерть, reset, выдачу/замену ЖДК и очередь обычного текста.                                                                                                                                                                                                                      | Текущий код делает reset до DWT gain и использует общую boundary/FIFO-модель. Это расходится с каноном: нужен gain/replacement до reset, attack-instance defer только для ATTACK-смертей и depth-first для non-ATTACK/direct-gain случаев.                                  |
| Главный приз          | `частично` | Дается, когда игрок стал причиной смерти врага через поддержанные `attack_damage`, `multi_target_attack` и player-caused `deal_damage`, включая защитную ветку. Переходит между игроками и дает чипсину в конце хода владельца. Self-kill и source-less Mayhem/Mega Mayhem death не двигают приз. | Нужно сохранять это правило при добавлении новых источников смерти, ЖДК-эффектов, перенаправлений и новых typed handlers.                                                                                                                                                   |

| --------------------- | ---------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |

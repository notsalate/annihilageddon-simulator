# Транзакции игровых действий

## Граница действия

`src/engine/actions.ts` — единственная публичная граница мутаций игрового
действия. После read-only preflight для `endTurn` она запускает действие через
`runActionTransaction` из `src/engine/action-transaction.ts`.

Транзакция считается успешной только при `result.ok === true`. Успешный
терминальный результат с `gameEndReason` фиксирует все изменения. Результат с
`ok: false` откатывает изменения и возвращается без изменений. Если сам откат
завершился ошибкой, транзакция выбрасывает техническое исключение, сохраняя
исходный `ActionResult` в его `cause`.

Исключение, возникшее внутри изменяющей состояние части действия, также
откатывает состояние и затем пробрасывается вызывающему коду; если сам откат
завершился ошибкой, она сохраняется в `cause` исходного исключения. Для
исключения, не являющегося объектом `Error`, выбрасывается техническая ошибка с
исходным значением и ошибкой отката в `cause`.

Для `endTurn` read-only preflight выполняется до создания снимка. Ошибка
проверки входных данных на этом этапе возвращается как обычный `ActionResult`
без мутаций. Исключения из callback выбора и из самой изменяющей части действия
проходят через транзакцию и сохраняются как технические исключения.

## Снимок и восстановление

Снимок охватывает:

- значения `GameState`, `turn`, ресурсы игроков и жизненные показатели;
- все физические зоны карт и их идентичность через Control Ledger, а также
  изменяемые объекты карт, жетонов, статусов и трофеев;
- usage-наборы текущего действия (`activatedCardIds`, списки полученных карт,
  damaging-идентификаторы и временный контроль);
- позицию seeded RNG и записи `eventLog`.

Откат сохраняет идентичность `GameState`, `PlayerState`, `CardInstance` и
массива `eventLog`. Для RNG гарантируется восстановление последовательности;
идентичность объекта RNG не является частью контракта. Приватное состояние
callback выбора принадлежит самому callback и не входит в снимок движка.

## Card Play Resolution

`src/engine/card-play-resolution.ts` — единый resolver для обычного `playCard`,
`play_top_card` и `play_top_card_from_foe_deck`. Он владеет размещением выбранной
карты, передачей ownership, порядком on-play триггеров и финальным перемещением
карты. Поиск и извлечение карты из исходной зоны, внешний action transaction и
специальные события вызывающего эффекта остаются у соответствующих callers.

`attack-defense.ts` сохраняет собственный последовательный nested savepoint для
добровольной Defense. Публичная транзакция действия не заменяет этот локальный
контур и не меняет его порядок отката.

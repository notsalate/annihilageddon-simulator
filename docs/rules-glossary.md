# Rules Glossary

Primary source: `Pravila_Krutagidon_2.pdf`. English correspondences are included only where the English rulebook section was used as a direct cross-check.

It has no main card type.                                                                                                                                            | RU p. 12; EN p. 13                      |

It has no main card type.                                                                                                                                    | RU p. 13; EN p. 14                      |

| --------------------------- | ----------------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |

| уничтожить карту            | `destroyCard`                       | destroy                   | Remove from normal game flow; some stack cards move back to their stack.                                                                                                                                                                                                                                                                                                                             | RU p. 12; EN p. 12                      |

## Project-Specific Naming

| Concept                                 | Preferred code/data name                                  | Notes                                                                                                                                                                                                                                |
| --------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Card definition                         | `CardDefinition`                                          | Unique data record, one per card definition.                                                                                                                                                                                         |
| Deck composition                        | `DeckComposition`                                         | `cardId + count`, not physical instances.                                                                                                                                                                                            |
| Card instance                           | `CardInstance`                                            | Per-game physical copy with stable instance id.                                                                                                                                                                                      |
| Card kind                               | `cardKind`                                                | Structural kind such as `wildMagic`, `limpWand`, `familiar`, `mayhem`, or normal deck card category.                                                                                                                                 |
| Main card types                         | `cardTypes`                                               | Set of main types used by type-based effects: `wizardCard`, `creature`, `spell`, `treasure`, `location`, and any explicitly mapped extra type.                                                                                       |
| Player zones                            | `deck`, `hand`, `discard`, `playedThisTurn`, `permanents` | Matches the executable canon in `docs/rules-canon.md`.                                                                                                                                                                               |
| Main market                             | `market`                                                  | Russian source term is `барахолка`; English source says `Line-Up`.                                                                                                                                                                   |
| Legend market                           | `legendMarket`                                            | Russian source term is `барахолка легенд`; English source says `Legendary Line-Up`.                                                                                                                                                  |
| Dead Wizard Token count for tie-breaker | `deadWizardTokenCount`                                    | Include DWT-like cards only if card/token data explicitly says they count as DWTs.                                                                                                                                                   |
| End-of-turn game check                  | `endOfTurnGameCheck`                                      | End the game after the current turn is completed and before passing clockwise when DWT is empty or this turn's actual Market Flow recorded a failed refill; never predict hidden event replacements or interrupt the current action. |
| ATTACK ability                          | `AttackAbility` / mapped ATTACK                           | Complete printed ability introduced by `ATTACK:`; its text can span several sentences and can start several Attack Instances.                                                                                                        |
| ATTACK text                             | `attackText`                                              | Instructions belonging to one ATTACK ability, including attached outcome clauses such as `if they die`.                                                                                                                              |
| Attack Instance                         | `AttackInstance` / `AttackId`                             | One separately started ATTACK with stable identity, Defense quotas, one or more target applications, and one DWT-defer boundary.                                                                                                     |
| Attack Application                      | `AttackApplication`                                       | Target-local branch of a multi-target Attack Instance; redirect changes this branch without creating a new instance.                                                                                                                 |
| Attack chain                            | `AttackChain`                                             | Sequence of separately started Attack Instances linked by a printed continuation condition; no implicit target/round cap and no empty-DWT ATTACK lock. Only a proven infinite continuation may receive an explicit cycle outcome.    |
| Attack-bound consequence                | `attackBoundConsequence`                                  | Consequence of a concrete ATTACK result that must finish before the instance closes.                                                                                                                                                 |
| Independent card ability                | `independentCardAbility`                                  | Later ability outside the preceding Attack Instance; deferred DWT text resolves before it.                                                                                                                                           |
| Defense window mode                     | `DefenseWindowMode`                                       | Explicit `PER_TARGET` or `COLLECT_ALL_FIRST` ordering for the concrete Attack Instance.                                                                                                                                              |
| Interactive multi-target ATTACK         | `COLLECT_ALL_FIRST`                                       | ATTACK whose shared text cannot be resolved for A without first knowing participation of B/C. Mayhem has its own special rule.                                                                                                       |
| DWT respawn modifier                    | `DwtRespawnModifier`                                      | Narrow token property needed to calculate the current reset; the only token property applied before respawn.                                                                                                                         |
| Attack-deferred DWT text                | `DeferredDwtResolution`                                   | Ordinary one-shot and Ongoing text waiting for the complete Attack Instance that caused its recipient's death; after closure, recipients begin in turn order and each recipient's multiple tokens retain gain order.                 |
| Direct DWT gain                         | `DirectDwtResolution`                                     | Gain without recipient death: no respawn; gain-time statuses/permanent rules and applicable one-shot/Ongoing text apply immediately to the actual recipient.                                                                         |
| Nested DWT resolution                   | `NestedDwtResolution`                                     | Depth-first handling of DWT text and deaths whose immediate source is not an ATTACK.                                                                                                                                                 |
| DWT interception                        | `DwtGainReplacement`                                      | Another player receives the token as direct gain before the defeated victim resets, including immediate statuses and nested effects; the victim still respawns without that token.                                                   |
| Control epoch                           | `controlEpoch`                                            | One uninterrupted period of control over a redirected application; eligible controller modifiers apply once per epoch.                                                                                                               |

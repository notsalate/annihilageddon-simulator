# Domain Docs

Read the relevant domain sources before changing or reviewing terms, game rules, or architecture:

- [CONTEXT.md](../../CONTEXT.md) is the repository's single domain glossary. Use its terms in code, tests, issues, and proposals.
- [Rules canon](../rules-canon.md) owns implementation rules. Use [open questions](../rules-open-questions.md) when a rule is unresolved.
- [ADR index](../adr/README.md) routes to existing architectural decisions; read those touching the changed area. Surface conflicts with an accepted ADR before proposing a different contract.
- For import or runtime data work, read [import pipeline](../import-pipeline.md) and [runtime layout](../runtime-layout.md), as applicable.

When a needed term is absent, check whether an existing glossary term fits. Record a real gap for domain modeling instead of introducing a competing synonym. Process documents in this folder do not establish game rules.

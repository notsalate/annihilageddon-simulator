# Проверка PhysicalCardLedger для #384–#389

Дата полного исторического замера: 2026-08-29. Дополнительный причинный
light-screen: 2026-08-30.

## Протокол

Analyzer сравнивался в свежих процессах, по десяти чередующимся парам
`AB/BA`. В каждой роли был один прогрев и три измерения; в отчёт попала
медиана. Окружение: Node `v22.23.1`, Windows `win32/x64`, `13th Gen Intel(R)
Core(TM) i5-13420H`, 12 логических процессоров. Исходная реализация — commit
`4b5cb653ef11530c13a8f7791b4a2446ae77f724`, Ledger — `96d08c2`.

Сводка исторического замера сохранена в этом отчёте. Локальный файл
`.scratch/tmp/physical-card-ledger-matched.json` позднее был перезаписан
незавершённым прогоном `b57eb2f` и больше не является сырым артефактом
commit `96d08c2`. Перед окончательным принятием результата полный протокол
нужно повторить на финальном commit.

## Регрессия глобальной membership-таблицы

Более поздний commit `b57eb2f` объединил принадлежность ветви и зону карты в
глобальном `WeakMap<CardInstance, number>` и начал записывать туда каждую карту
каждого fork. Девять завершённых пар `light` показали медиану `27 378,37 мс`
против `4 386,40 мс` у исходной реализации. Последовательные измерения внутри
одного процесса сильно росли, что согласуется с накоплением служебных записей
до их обработки GC.

Изолированный причинный A/B изменил только способ хранения той же упакованной
метки: вместо глобального `WeakMap` она стала non-enumerable `Symbol`-полем
branch-local объекта карты. В каждой роли запускался свежий процесс с одним
прогревом и тремя измерениями:

| Порядок | Медиана `WeakMap` | Медиана скрытой метки | Ускорение |
| ------- | ----------------: | --------------------: | --------: |
| `AB`    |    `32 146,81 мс` |         `1 971,61 мс` |  `16,31×` |
| `BA`    |    `22 173,44 мс` |         `2 012,11 мс` |  `11,02×` |

У `WeakMap` отдельные измерения колебались от `3 072,64` до `44 220,57 мс`;
скрытая метка во всех шести измерениях оставалась в диапазоне
`1 955,56–2 082,57 мс`. Workload, volume, result fingerprints и метрики дерева
совпали во всех ролях. Это изолирует глобальный `WeakMap` как причину
регрессии полного времени. Peak-memory этого короткого screen меняется
неоднозначно и не заменяет retained-memory probe.

Сырые JSON обеих порядковых пар сохранены локально:

- `.scratch/tmp/physical-card-ledger-weakmap-vs-hidden-tag-raw.json`;
- `.scratch/tmp/physical-card-ledger-weakmap-vs-hidden-tag-ba-raw.json`.

Отдельный end-to-end screen сравнил текущий Ledger с исходной реализацией до
Ledger:

| Роль                     |             Измерения полного времени |       Медиана | Медиана peak memory |
| ------------------------ | ------------------------------------: | ------------: | ------------------: |
| исходная `4b5cb65`       | `3 360,31`; `3 311,59`; `3 402,48 мс` | `3 360,31 мс` |       `303 996 928` |
| Ledger со скрытой меткой | `2 130,85`; `2 008,63`; `1 980,47 мс` | `2 008,63 мс` |       `388 259 840` |

Workload, volume, result fingerprints и метрики дерева совпали. Этот screen
показывает предварительное end-to-end ускорение `1,67×` относительно исходной
реализации, но сам по себе не доказывает причину. Один screen не заменяет
требуемые десять пар, остальные профили, Simulation и retained-memory probe.
Число peak memory также остаётся выше исходного и требует полноценной проверки
по протоколу #389.

Полный JSON обеих ролей end-to-end screen сохраняется локально в
`.scratch/tmp/physical-card-ledger-hidden-tag-screen-raw.json`. Это
диагностический run product, поэтому по правилам benchmark он не добавляется
в Git.

## Устранённая стоимость поиска

Сравнение тяжёлого диагностического прогона показывает, что Ledger убрал
старый глобальный путь `ID → listPhysicalCardLocations`:

| Счётчик                           | Исходная реализация |     Ledger |
| --------------------------------- | ------------------: | ---------: |
| точечные поиски                   |           1 214 045 |          0 |
| просмотренные карты               |         272 352 102 | 14 403 500 |
| полные списки расположений        |           1 232 108 |     26 962 |
| созданные записи расположений     |         253 747 465 |  5 527 772 |
| изменения физических расположений |           2 635 295 |  2 635 295 |

`26 962` полных списков и оставшиеся проходы принадлежат отдельным
module-owned операциям: fork/clone, проверке ветки, снимкам и аналитическим
потребителям. Они не являются возвратом старого point-lookup API.

В исходном CPU-профиле главным проектным hotspot был
`listPhysicalCardLocations` — 7 429,70 мс sampled self-time; GC занимал
6 331,03 мс. В Ledger-профиле `listPhysicalCardLocations` исчез из hotspot-ов;
основные остаточные категории — GC 3 998,33 мс, `cloneLedgerValue` 1 296,82 мс,
`seedClonedMembership` 562,83 мс и `clonePhysicalCardLedger` 446,20 мс.
Sampled allocation Ledger составил 17,56 МиБ; главным проектным местом был
`replaceZone` — 8,00 МиБ. Эти числа диагностические и не являются точным
подсчётом всех выделений.

## Проверка Simulation

Десять пар `AB/BA` для stage `100` выполнялись в свежих процессах. Workload
fingerprint совпал, но result и объём событий разошлись во всех десяти парах:

| Метрика | Исходная реализация |  Ledger |
| ------- | ------------------: | ------: |
| turns   |               3 823 |   3 831 |
| actions |              29 332 |  29 383 |
| events  |             157 106 | 157 424 |

Исходный result fingerprint:
`f6e75f4b6b8683608b3a6f1fe4dea4021f684f15112347d565769cedb3f8d48a`.

Ledger result fingerprint:
`b9c8a3f9d755eded69f9be08124f59a86bf929966e6b2e29bb5f4d4c290060d5`.

Первая расходимость возникает при вложенном `Mega Mayhem` во время Market
Flow. Старая реализация продолжает работать со stale-массивом и повторно
открывает карты, которые вложенный эффект уже уничтожил. В Ledger Market Flow
читает актуальную зону и пропускает эти карты. Старый путь приводит к
дублированию физической карты: одна из таких карт оказывается одновременно в
`destroyedPile` и `mainMarket`; строгая проверка Ledger это запрещает. Для этого
случая добавлен регрессионный тест, фиксирующий физическую уникальность.

Таким образом, несовпадение является обнаруженной корректностью старого
stale-array поведения, а не доказанной потерей производительности. Однако
строгий критерий #389 «одинаковый Simulation result fingerprint» пока не
пройден: перед закрытием issue нужен либо совместимый с физической
уникальностью способ сохранить старую семантику, либо явное принятие нового
baseline и исправления поведения как изменения результата.

## Итог

- #384–#388 покрыты архитектурой Ledger, живыми ссылками, явными ID-границами,
  module-owned операциями зон и регрессионными проверками.
- Полный исторический замер commit `96d08c2` показал `1,65×`, `1,76×` и
  `1,44×` на `light`, `typical` и `heavy`, но не является финальным замером
  текущей реализации.
- Изолированные `AB/BA` screens показали ускорение `11,02–16,31×` от замены
  глобального `WeakMap` скрытой меткой; отдельный end-to-end screen показал
  `1,67×` относительно исходной реализации на `light`.
- #389 не следует считать полностью закрытым до решения по Simulation
  fingerprint, десяти финальных пар каждого профиля и retained-memory probe.

Полный парный протокол, Simulation и probe удерживаемых состояний находятся во
временных файлах `.scratch/tmp/`; они не являются частью runtime-данных и не
должны попадать в commit. Перед запуском нужно собрать `dist/` и заменить в
скриптах reference/current commit на сравниваемые ревизии, если они изменились.

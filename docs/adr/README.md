# Architecture Decision Records

ADR фиксирует долговременное правило, а не пересказывает реализацию. Решение требует ADR, если оно трудно обратимо, неочевидно или содержит существенный долгосрочный компромисс.

## Жизненный цикл

- `proposed` — новое решение зафиксировано в момент выбора правила и готово к архитектурному ревью.
- `accepted` — решение принято и является действующим правилом.
- `superseded` — решение заменено новым ADR, но его документ сохраняется.

Историческое решение получает `origin: restored`. Поле `recorded` содержит дату восстановления документа, а `decision_date: unknown` честно отмечает, что исходная дата принятия не подтверждена. Для нового решения `origin: new`, а `decision_date` — дата выбора правила.

Запрашивать ADR в ревью можно только с указанием прежнего правила, нового правила и долговременного последствия. Размер PR, название ветки или слово `refactor` сами по себе недостаточны.

## Формат

Каждый ADR хранится в отдельном файле `NNNN-kebab-case.md` и начинается с YAML-подобного заголовка:

```text
---
id: ADR-0001
title: Заголовок решения
status: proposed
origin: new
recorded: 2026-08-21
decision_date: 2026-08-21
supersedes: none
superseded_by: none
---
```

Допустимые значения `status`: `proposed`, `accepted`, `superseded`. Допустимые значения `origin`: `new`, `restored`. Поля `supersedes` и `superseded_by` содержат `none` или список идентификаторов ADR через запятую. При замене старый документ сохраняется со статусом `superseded`, а новая и старая записи ссылаются друг на друга.

После заголовка обязательны разделы:

```markdown
## Контекст

## Решение

## Альтернативы

## Причины выбора

## Последствия

### Положительные

### Отрицательные

## Доказательства
```

Раздел `Решение` описывает правило, а не последовательность изменений в коде. В `Доказательства` перечисляются подтверждающие материалы. Для восстановленного ADR материалы должны позволять отделить установленный факт от неизвестной исторической мотивации.

## Индекс и проверка

`index.md` содержит одну строку на каждый ADR: идентификатор, статус, заголовок, ссылку на документ, происхождение и связи замены. Скрипт проверяет только проверяемые свойства формата: обязательные поля и разделы, уникальность идентификаторов, соответствие индекса, существование файлов и двусторонние ссылки замены. Он не пытается угадывать архитектурный смысл изменения.

```powershell
npm run validate:adr
```

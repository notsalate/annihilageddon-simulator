# ADR-0002: Граница runtime data и import-слоёв

## Контекст

Проект хранит исходные изображения, исходный текст, черновые JSON-файлы, runtime JSON и манифесты пакетов. Эти материалы имеют разные степени доверия и разные контракты. Движок должен выполнять воспроизводимую игру, а import-слой должен сохранять видимые факты и неопределённости до отдельного преобразования в runtime-данные.

## Решение

Движок читает только декодированные runtime-описания и состав из пакета runtime-данных. Исходный текст, черновые JSON-файлы, файлы OCR/import и промежуточные реестры не являются входом партии и не разбираются во время симуляции.

Runtime JSON содержит стабильные идентификаторы, поля движка и явные эффекты. Манифест пакета явно перечисляет описания и состав. Входные runtime-данные проходят decoder на границе движка; инструменты import могут создавать или проверять runtime-файлы, но не становятся скрытым источником поведения.

## Альтернативы

- Читать черновые JSON-файлы или исходный текст непосредственно во время партии. Текущие материалы показывают, что этот путь не используется; рассматривался ли он исторически, неизвестно.
- Объединить import и runtime JSON в один формат. Это смешивает видимые факты с исполняемыми решениями; неизвестно, рассматривался ли вариант исторически.
- Принимать runtime JSON без decoder и полагаться на форму файлов. Текущая граница decoder показывает действующее решение; было ли это альтернативой при первоначальном выборе, неизвестно.

## Причины выбора

Разделение позволяет отдельно проверять источник, преобразование и исполняемую схему. Runtime-пакет остаётся самодостаточным и не зависит от локальных черновиков или путей к ресурсам, а декодирование превращает внешний JSON в проверенный контракт движка.

## Последствия

### Положительные

- Запуск игры не зависит от import-источников и состояния локального процесса OCR/подготовки черновиков.
- Runtime-данные можно проверять, версионировать и сравнивать как отдельный исполняемый пакет.
- Ошибки формы данных обнаруживаются на границе до изменения игрового состояния.

### Отрицательные

- Новая карта требует отдельного шага преобразования между черновиком и runtime-данными.
- Нужно поддерживать несколько связанных форматов и явный манифест пакета.
- Быстрые эксперименты с исходным текстом нельзя автоматически считать исполняемыми.
